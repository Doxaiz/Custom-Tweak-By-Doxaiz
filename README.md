# Custom Tweak By Doxaiz

**Честная оптимизация игрового соединения в Windows 10/11.**<br>
Находит сетевой поток игры, измеряет задержку до игрового сервера, пробует более короткий маршрут,
применяет настройки сетевого стека Windows — и говорит цифрами, стало ли быстрее.<br>
Всё, что она меняет, возвращается одной кнопкой.

## Что она делает

| | |
|---|---|
| **Одна кнопка** | «Оптимизировать соединение»: замер «до», поиск пути, применение, проверка «после». Кнопка «Остановить» возвращает всё как было. |
| **Маршрут только для игры** | Маршрут добавляется к адресу игрового сервера и снимается после остановки. Это не глобальный VPN: остальной трафик идёт как обычно. |
| **Приоритет пакетов** | Политика QoS помечает пакеты процесса игры как сетевое управление: Windows ставит их в очередь раньше остальных. Дальше приоритет сохраняется настолько, насколько его уважает ваш роутер и провайдер — программа этого не обещает. |
| **47 твиков** | С честным вердиктом у каждого: 23 «включать: да», 18 «по желанию», 3 «осторожно», 3 «не советуем». Пять подкатегорий (пинг, система, кадры, скорость, ввод), пять пресетов — от «Низкого пинга» (19 твиков) до «Вернуть как было». |
| **Замеры, а не обещания** | Пинг, джиттер, потери, физический предел пути. Если измерить не удалось — так и написано, нулей и «0 мс» не бывает. |
| **Безопасный откат** | Снапшот «до», журнал «что и когда менялось», журнал предзаписи: после аварии остатки снимаются при следующем старте. |

| `SHA256SUMS.txt` | контрольные суммы всех файлов | — |

Установщик не подписан сертификатом, поэтому Windows покажет «Windows protected your PC»:
«Подробнее» → «Выполнить в любом случае», а в запросе прав издателем будет «Неизвестный издатель».
Сертификат EV этого не исправил бы: с 2024 года тип сертификата на предупреждение SmartScreen не влияет —
доверие набирается загрузками ([документация Microsoft](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)).
А если в Windows 11 включён Smart App Control, неподписанный файл не запускается вовсе — обходить эту
защиту программа не советует. Что делать в каждом случае и как сверить SHA-256 —
[`docs/УСТАНОВКА.md`](docs/УСТАНОВКА.md).

## Три шага

1. **Запустите игру** и зайдите в матч (или в меню, где идёт обмен с сервером).
2. **Нажмите «Оптимизировать соединение».** Программа найдёт живой поток игры, замерит задержку и предложит путь.
3. **Смотрите два числа** — «было» и «стало», и физический предел пути. Не помогло — «Остановить»: маршрут и политика снимаются.

## Как это выглядит

Интерфейс собран в двух HTML-страницах, которые генерируются из настоящего кода при каждой сборке:

- **[`docs/custom-tweak-by-doxaiz.html`](docs/custom-tweak-by-doxaiz.html)** — витрина: главный экран, карточки твиков, маршруты, журнал, настройки. Откройте файл в браузере.
- **[`docs/pingforge-ui-preview.html`](docs/pingforge-ui-preview.html)** — подробный рабочий документ интерфейса на палитре программы.

Страницы не рисуются вручную: числа, твики и формулировки берутся из каталога и моделей представления,
поэтому витрина не может разойтись с программой. Совпадение проверяется автоматически на каждой сборке: 122 проверки
подробного макета и 77 проверок витрины — цвета, формулировки, все 47 карточек, шесть примеров файлов
и арифметика готовности: сумма весов, итог по формуле и число автотестов из журнала прогона.

Настоящий снимок окна снимается на сборочной Windows при каждом прогоне и лежит в артефакте
**`test-results-and-logs`** последнего прогона во вкладке **Actions** (файл `app-window.png`,
хранится три дня — таков лимит хранилища, поэтому в репозитории снимков нет).

## Одно имя, одна программа

Программа одна — **Custom Tweak By Doxaiz**. Отдельной программы «PingForge» нет — ни «лайт», ни «про»-версии:
всё, что делает проект, делает она же. Имя **PingForge** осталось техническим — так называются служба,
её канал и её папка данных:

| Где видно | Что написано | Почему так |
| --- | --- | --- |
| Список служб Windows | `Custom Tweak By Doxaiz — служба` | видно имя программы, а не второй продукт |
| Имя службы (`Get-Service`) | `PingForge` | по нему службу находят скрипты, самопроверка и уже установленные версии |
| Папка данных | `%ProgramData%\PingForge` | журнал изменений и снапшоты у тех, кто уже обновился, остаются на месте |
| Канал службы | `\\.\pipe\PingForge.Engine.v1` | смена имени канала — это разрыв связи с уже установленной службой |

Переименование этих трёх имён отложено осознанно: оно даёт человеку ровно ноль пользы и теряет данные.
Проверки следят, что наружу программа называется одним именем: тест читает README, архитектуру и службу,
а страницы интерфейса проверяются на сборке — если где-то появится «вторая программа», прогон упадёт.

## Что программа не делает никогда

- не лезет в память игры, не инжектит DLL, не эмулирует ввод;
- не отключает Windows Defender, брандмауэр, UAC, проверку подписи драйверов и обновления безопасности;
- не подменяет MAC-адрес, не меняет файл подкачки, не трогает безопасную загрузку;
- не отключает системные службы и не «оптимизирует» всё подряд без спроса;
- не отправляет наружу ни статистику, ни журналы, ни настройки — всё остаётся на диске
  (`%ProgramData%\PingForge` и журнал запуска в `%LOCALAPPDATA%\CustomTweakByDoxaiz`).

Это не обещание в документации: список запретов лежит в коде (`CatalogSafetyAudit`) и проверяется тестом —
если кто-то добавит твик, выключающий Defender, сборка упадёт.

## Чего ждать от цифр

Твики дают единицы миллисекунд. Основные десятки даёт смена пути — и только если более короткий путь
действительно существует. Если выигрыша нет, программа так и напишет: «прямое подключение не хуже».
Физический предел пути показывается рядом с результатом: ниже него не даст даже идеальный маршрут.

## Сборка из исходников

Нужен **.NET SDK 10** (версия закреплена в `global.json`) и Windows для сборки оконной части.

```powershell
git clone https://github.com/Doxaiz/Custom-Tweak-By-Doxaiz.git
cd Custom-Tweak-By-Doxaiz

dotnet build PingForge.slnx -c Release     # вся сборка
dotnet test  tests/PingForge.Tests         # автотесты
```

Макет интерфейса и его проверки:

```bash
dotnet run --project tools/PingForge.CatalogDump -c Release -- docs/catalog.json
python3 tools/render_ui_preview.py docs/catalog.json docs/pingforge-ui-preview.html
python3 tools/render_app_site.py   docs/catalog.json docs/custom-tweak-by-doxaiz.html
node tools/check_ui_preview.js docs/pingforge-ui-preview.html
node tools/check_app_site.js   docs/custom-tweak-by-doxaiz.html
```

Всё это же делает CI на каждый push: сборка решения, автотесты на Windows, проверки макета,
живая проверка окна (`--self-check`), тихая установка → служба → живой разговор по каналу → тихое удаление,
и сборка шести файлов релиза.

## Структура

| Проект | Что внутри |
|---|---|
| `PingForge.Core` | модели, настройки, журналы с поворотом, отчёты о падении, пакет поддержки |
| `PingForge.Probing` | замеры задержки и потерь, физический предел пути |
| `PingForge.Analysis` | разбор сетевого потока игры, качество соединения, график |
| `PingForge.Routing` | справочник маршрутов, поиск узлов, выбор пути |
| `PingForge.Network` | каталог игр и процесс игры, детектор потока, свои игры |
| `PingForge.Tweaks` | каталог твиков, вердикты, пресеты, аудит запрещённого |
| `PingForge.Data` | база журнала (SQLite), снапшоты |
| `PingForge.Service*` | служба: меняет систему от имени администратора, протокол и каналы |
| `PingForge.App`, `PingForge.App.ViewModels` | окно WPF и модели представления (без оконной логики в моделях) |
| `PingForge.SystemState`, `PingForge.Orchestration` | чтение состояния системы, оркестрация изменений и откатов |
| `tools/` | вывод каталога, проверка службы, генераторы макета |

Подробнее — [`docs/АРХИТЕКТУРА.md`](docs/АРХИТЕКТУРА.md) и [`docs/КАНАЛЫ-СЛУЖБЫ.md`](docs/КАНАЛЫ-СЛУЖБЫ.md).
