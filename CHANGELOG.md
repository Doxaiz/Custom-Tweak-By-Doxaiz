# Журнал изменений — Custom Tweak By Doxaiz

Все важные изменения по версиям. Формат: Added / Changed / Fixed / Security.

## [Не выпущено]
### Added
- Целостность базы (задача U): при старте службы — `PRAGMA quick_check` **до** создания схемы. Испорченный файл не удаляется, а откладывается рядом (`pingforge.db.corrupt-<метка>`); читаемая резервная копия ставится на место. Если копий нет или они тоже не читаются — служба поднимается с чистой базой, а прежний файл остаётся для разбора.
- Резервные копии базы (задача U): средствами SQLite (онлайн-backup), одна в сутки и одна перед каждым применением твиков, хранятся последние три (`DatabaseBackupService.KeepBackups = 3`). Копия перед применением — `BackupBeforeApplyCoordinator`; сбой копирования не блокирует применение, но пишется в журнал службы.
- Тесты `DatabaseMaintenanceTests` (9): повреждение видно как повреждение, копия возвращает снапшоты, испорченный файл не пропадает, копий не больше трёх, суточная копия не делается на каждом запуске, копия снимается до применения, плюс сторож «служба действительно вызывает проверку и обёртку копии». Подтверждены зелёным прогоном `43874343076` (PR №16): сборка, тесты, витрины, установщик и живая проверка на Windows.

### Changed
- Ответы службы `ping` и `status` сообщают о состоянии базы, если при запуске пришлось начинать с чистой: «ВНИМАНИЕ: …» с причиной и именем сохранённого файла — про пропавшие снапшоты человек узнаёт сразу, а не при попытке отката.

### Fixed
- `DatabaseBackupService` был объявлен, но не вызывался ниоткуда: проверки целостности и копий при запуске службы фактически не было. Теперь он подключён к старту службы и к применению твиков.

## [0.2.0] — 2026-10-20
### Added
- Мультипуть на своих линиях (без чужой сети): основной узел + горячий резерв. Программа меряет все пути к серверу игры временными `/32`, выбирает лучший основным, второй — резервом; без своей сети пакеты не дублируются по интернету — переключение сменой маршрута за 1–2 с при просадке. Честно: нужен второй шлюз (Ethernet + Wi-Fi/модем/VPN), иначе мультипуть не включается. Блок в «Настройках» → «Сервер маршрутизации» с чекбоксом, кнопками «Основной/Резерв», подсказками и `RoutingMeasureDto.RunnerUpAddress`; `RoutingSettings.MultipathEnabled` + `RoutingSecondaryNode` в общем `settings.json` с терпимым чтением.
- `RoutePathComparisonReport.RunnerUp` и вердикт с пометкой резерва.

### Changed
- `RoutingPathOptionsProvider` держит `LastSecondaryRoute`/`LastMultipathRu` и пишет в вердикт «Резерв — …: горячий шлюз на случай просадки».

### Fixed
- Дублирующий список узлов в «Настройках» убран.

## [0.1.0] — 2026-10-20
### Added
- Базовый продукт: 47 твиков (TCP, QoS, NIC, ввод), пресеты, снапшоты, откат, восстановление.
- Свои игры: добавить `.exe`, переименовать/удалить, общий `settings.json` под мьютексом, `.bak` и карантин битого JSON, детектор — `Untested` + «своя игра: анти-чит неизвестен».
- Маршрутизация: узлы только из реальных шлюзов и VPN-адаптеров таблицы маршрутов + ручной ввод IPv4, команды `route-discover`/`route-measure`, временный `/32` со сверкой таблицы, «прямой путь короче — ничего не меняем», честное предупреждение про третью сторону.
- Регионы и порты игр из `GameRouteCatalog` в карточке «Игры», честная карточка «DNS — это про вход, а не про пинг» с 5 бесплатными резолверами; платные способы не показываются.
- Живая оптимизация: поиск потока → замер «до» → маршрут `/32` + QoS DSCP 46 → контроль каждые 2 с → честный итог; без игры — честный отказ.
- Анализ сети: график RTT min/avg/p95, джиттер и потери (1/5/15 мин, разрывы вместо нулей, только живые замеры), карточка задержки ввода, блок проверки настроек.
- Проверка сети одной кнопкой (7 пунктов: MTU, DNS, двойной NAT/CGNAT, bufferbloat, Wi-Fi, фоновые загрузки, права/служба) — ничего не меняет, итог с приоритетами.
- Путь до сервера по хопам (до 60 с, отмена): адрес, средний RTT, p95, потери, «не отвечает» без чисел, подсветка наибольшего прироста без утверждения виновника, только при живом потоке.
- История сессий (схема v5, `route_optimization_sessions`): вкладка «Сессии» в Журнале — «было → стало» и разница, сравнение двух сессий, график среднего RTT по дням для одного сервера, команды `sessions`/`sessions-clear`.
- Прозрачность изменений: экран «Что изменилось» — `previousText → verifiedText` («не удалось прочитать»), сводка изменено/уже было/ошибок, кнопка «Вернуть только это» (`rollback-tweak`).
- Журнал: фильтры по типу/статусу/дате, поиск по коду/причине, пагинация «Показано X из Y» + «показать ещё», лимит из настроек (по умолчанию 200, предел 500), выгрузка CSV с экранированием, «ничего не нашлось» с подсказкой.
- Команда «Вернуть всё как было» (трей + Настройки): остановить оптимизацию → снять QoS → маршруты → откатить твики → проверить остатки, честный отчёт по шагам.
- Политика хранения снапшотов: хранить последние 10, не удалять новее 30 дней, снапшоты с незакрытыми операциями не удаляются никогда; экран «Сколько занимает база» с кнопкой «Почистить».
- Версии окно↔служба: сверка `appVersion`/`protocolVersion`, карточка «Служба другой версии» при несовпадении протокола, предупреждение при различии версии программы; `app.manifest` `asInvoker` + `PerMonitorV2`.
- Смена сети/сон/VPN: `NetworkStateMonitor` — события сон/пробуждение/адаптер/сеть пропала/вернулась/VPN, пауза сессии, «замер устарел», снятие маршрута, «путь через VPN».
- Логи с ротацией 5 МБ × 3, локальный дамп при падении (`ProgramData\PingForge\crash`), пакет для поддержки ZIP ≤20 МБ с экраном «что попадёт в пакет».
- Экспорт/импорт/сброс настроек: JSON с версией схемы и датой, проверка схемы, выбор слияние/замена, сброс с бэкапом, импорт не применяет твики.
- Выбор игры: список найденных игр (имя/процесс/адрес:порт/тип), переключение на ходу с остановкой прежних изменений, кандидаты не выбираются до добавления.
- Удаление без следов: `UninstallGuard` (3 варианта: вернуть и удалить / оставить / отмена), `uninstall-check`, `uninstall-service.ps1` с опросом службы, NSIS останавливает службу перед обновлением, живой цикл A/B проверен.
- Целостность БД: `PRAGMA quick_check` при старте, режим «база повреждена» с предложением восстановить/начать чисто, резервные копии SQLite-онлайн (раз в сутки + перед применением, последние 3), честный отказ при нечитаемом снапшоте, проверка повреждённого файла в CI.
- Выпуск: `CHANGELOG.md`, заметки релиза из шапки CHANGELOG + SHA-256, линтер честности (запрещённые обещания), честный текст про отсутствие подписи EV.
- Безопасность каналов (C1–C6): проверка токена клиента, два канала (основной + чтение), `PipeAclFactory` без `Everyone`/`S-1-5-4`, мьютекс настроек, `PerMonitorV2` и т. д.
- Защита от UDP 0.0.0.0:0 через ETW `Microsoft-Windows-Kernel-Network` (42/43/58/59, `RecentUdpPeerStore` 30 с / 4096, отсев собственных/приватных), честный откат при ошибке ETW.
- Кэш вердикта маршрута по процессу **и** адресу:порту сервера (`DecisionKey`).

### Security
- Два канала службы с ACL Windows, проверка токена клиента, запрет `Everyone`/`S-1-5-4`.

Известные ограничения (актуально для 0.2.0):
- Мультипуть требует второго шлюза и измеренного выигрыша: без второго провода программа честно остаётся на одном пути.
- Установщик без подписи EV — SmartScreen предупреждает; проверяйте SHA-256 из SHA256SUMS.txt в релизе.
- Маршрут требует выбранного узла и живой игры; без них — честный отказ, а не выдумка.
- Проверка выигрыша на машине с игрой — отдельный прогон у человека; на сборочной машине игры нет.

Известные ограничения (было для 0.1.0):
- Установщик без подписи EV — SmartScreen предупреждает; проверяйте SHA-256 из SHA256SUMS.txt в релизе.
- Маршрут требует выбранного узла и живой игры; без них — честный отказ, а не выдумка.
- Проверка выигрыша на машине с игрой — отдельный прогон у человека; на сборочной машине игры нет.
