# Основания в открытых источниках

Здесь собраны факты, которые программа утверждает о чужих играх и сервисах, и то, откуда они взяты.
Правило простое: справочники в коде называют основание, а не «так принято считать». Если
источник говорит меньше, чем хотелось бы, так и записано: «не публикует», «фиксируют сообщества»,
«старая запись не уточняет».

Проверено в ноябре 2026 года. Ссылки ведут на страницы издателей и разработчиков там, где они есть;
сообщества указаны как сообщества, а не как официальный источник.

## Подпись файла, SmartScreen и Smart App Control

| Что сказано в программе | Основание |
| --- | --- |
| Установщик не подписан: Windows покажет «Windows protected your PC» («Подробнее» → «Выполнить в любом случае»), а в запросе прав издатель не назван («Неизвестный издатель») | Microsoft Learn, «SmartScreen reputation for Windows app developers», строка «No signature»: «Warning — „Windows protected your PC“; User must choose „Run anyway“ before the app can run. Enterprise policy can prevent continuation entirely»: <https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation> |
| Подпись сама по себе не снимает предупреждение: SmartScreen смотрит на репутацию файла (хеш) и издателя (сертификат), и новый файл может предупредить даже с подписью | там же: «Even when signed, a newly created binary could still show a SmartScreen warning until its hash or publisher certificate accumulates sufficient evidence of positive reputation»; ручной отправки на проверку для обычных устройств нет — репутация копится загрузками |
| **Сертификат EV больше не снимает предупреждение с первого скачивания** — это поведение убрано в 2024 году, поэтому «купить EV, и предупреждение исчезнет» неправда | Microsoft Learn, «SmartScreen reputation»: «EV certificates no longer bypass SmartScreen … they no longer impact SmartScreen behavior. Paying a premium for EV solely to avoid SmartScreen warnings is no longer justified»; «Code signing options»: у EV в графе SmartScreen — «Same as OV since 2024 — no longer instant bypass», у варианта «No signature» — «Strong SmartScreen block; enterprises may block entirely»: <https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options> |
| При включённом Smart App Control в Windows 11 неподписанный файл не запускается вовсе — кнопки «всё равно запустить» нет | Microsoft Learn, «SmartScreen reputation»: «Smart App Control will block execution of unsigned files … unless the file has a positive reputation. Smart App Control signature checks apply to all executable files, not just those downloaded from the Internet»; подробности: «Smart App Control overview» — разрешён только код, распознанный службой безопасности Microsoft, или подписанный сертификатом из Trusted Root Program: <https://learn.microsoft.com/en-us/windows/apps/develop/smart-app-control/overview> |
| Проверить блокировку Smart App Control можно в журнале CodeIntegrity: событие 3077 (блокировка) и 3076 (режим проверки) | Microsoft Learn, «App Control for Business» и разборы событий CodeIntegrity: <https://learn.microsoft.com/en-us/windows/security/application-security/application-control/app-control-for-business/appcontrol> |
| Подпись и хеш проверяются локально, без интернета: `Get-AuthenticodeSignature` и `Get-FileHash -Algorithm SHA256` | Справка PowerShell по этим командлетам; в самой программе подпись читается локально и наружу не уходит |

## Профиль пользователя и служба

| Что сказано | Основание |
| --- | --- |
| `HKCU` — это ветка того процесса, который читает или пишет; у службы под LocalSystem она своя, системная, и к профилю человека не относится | Microsoft Learn, «Registry Hives» и описание `HKEY_CURRENT_USER`: <https://learn.microsoft.com/en-us/windows/win32/sysinfo/registry-hives> |
| Профиль конкретного человека открывается как `HKEY_USERS\<SID>`; SID вошедшего пользователя берётся из токена его сеанса | Microsoft Learn, `WTSQueryUserToken` и `WTSGetActiveConsoleSessionId`: <https://learn.microsoft.com/en-us/windows/win32/api/wtsapi32/nf-wtsapi32-wtsqueryusertoken>, <https://learn.microsoft.com/en-us/windows/win32/api/kernel32/nf-kernel32-wtsgetactiveconsolesessionid> |
| Поэтому настройки пользователя программа применяет по SID запросившего, а без него — по активному сеансу; если ни того, ни другого нет, твик отказывается, а не пишет в профиль службы | Это правило программы, проверяется тестами и живым прогоном: `tools/c7-live-checks.ps1` читает значения своим процессом своей учётной записи |

## Что программа не утверждает

- **Адреса дата-центров.** Игры их не публикуют как список, а матчмейкер выдаёт сервер на матч.
  Поэтому в справочнике регионы, а конкретный адрес программа узнаёт из живого потока игры.
- **Перехват пакетов.** В программе его нет ни для одной игры: маршрут и приоритет пакетов (QoS) —
  настройки Windows. Подробнее: [docs/АРХИТЕКТУРА.md](АРХИТЕКТУРА.md).
- **Совместимость с анти-читами.** Ни для одной игры она не подтверждена живой проверкой; там, где
  это важно, стоит «не проверяли», а не «безопасно».

## Как это проверяется

Факты в справочниках — не текст «на память»: тесты сверяют ключевые из них с ожидаемыми значениями
(`RouteCatalogTests`, `AntiCheatNotesTests`). Если факт меняется, падает тест, а не тихо устаревает
подпись в окне. Ссылки из этой страницы — основание для правки: они объясняют, **почему** в коде
стоит именно это число, а не живой замер на вашей машине.
